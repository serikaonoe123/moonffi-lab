# 依赖与状态感知缩减：对照实验

验证日期：2026-10-17（Asia/Shanghai）。Windows x64 / MSVC，MoonBit native debug，async 0.22.5。

实验验证共享引用和扩缩容约束下的候选修整，以及缩减结果的删除最小性声明。最新一轮扩展至 21 个固定案例，每种策略重复三次：state 消除了无效候选；一个共享场景中 dependency/state 得到 4 步结果，plain 为 6 步。但 state 没有降低总工作进程执行次数，也没有显示优于 dependency 的最终步数。

## 21 例、三轮重复实验

`scripts/benchmark-reduction.ps1` 默认保留原来的九例，并新增 `buffer-stateful-1` 的 seed 17、18、19、20 × nul/share/error，每条 64 步，共十二例。它们是上一轮生成实验 seed 17–80 的前四个连续 seed，不是新的独立留出集，也没有按缩减表现挑选。三个模式均为明确标注的人工缺陷。

脚本在计时前写入 `protocol.json`，记录 seed、顺序规则、预算、脚本与二进制哈希和环境；生成所有输入后冻结哈希，先逐一重放，保留全部筛选结果于 `screening.json`。只有观测到性质失败的输入进入缩减；通过的输入不会被替换成其他失败输入。本轮 21/21 都出现性质失败。

每例每策略重复三次，共 **189 次缩减**。执行顺序按“重复序号 + 案例序号”循环旋转，因此三轮内每种策略在每个位置恰好出现一次。每次仍为 200 个工作进程、60 秒墙钟预算；所有测量都保留，包括未完成或预算耗尽的结果，不丢弃预热样本。原始逐次数据、按例的中位数/最小值/最大值分别写入 `measurements.json`、`aggregate.json`，并生成 `comparison.md`。

最新实测保存在 `results/benchmark-repeated-final-20261017`，结构化摘要见 [重复实验快照](evidence/reduction-repeated-20261017.json)。所有 189 次均完成搜索与失败确认；63 个“案例 × 策略”组合的三轮具体缩减输入、候选数、工作进程次数和停止状态一致。以下计数为每轮合计，三轮相同；不是把三轮当成额外独立案例。

| 语料 | 策略 | 候选提议 | 无效候选 | 工作进程执行次数 |
|---|---|---:|---:|---:|
| 全部 21 例 | plain | 762 | 333 | 555 |
| 全部 21 例 | dependency | 475 | 14 | 587 |
| 全部 21 例 | state | 474 | 0 | 600 |
| 新增 12 例 | plain | 565 | 268 | 369 |
| 新增 12 例 | dependency | 309 | 13 | 368 |
| 新增 12 例 | state | 309 | 0 | 381 |

新增语料的具体结果如下，单元格中均为 plain / dependency / state 的顺序。步数及工作进程次数在三轮一致。

| 案例 | 最终步数 | 工作进程次数 |
|---|---|---|
| nul-17 | 2 / 2 / 2 | 18 / 25 / 25 |
| share-17 | 4 / 4 / 4 | 33 / 31 / 31 |
| error-17 | 3 / 3 / 3 | 22 / 29 / 29 |
| nul-18 | 2 / 2 / 2 | 24 / 25 / 27 |
| share-18 | 4 / 4 / 4 | 53 / 33 / 35 |
| error-18 | 3 / 3 / 3 | 21 / 27 / 27 |
| nul-19 | 2 / 2 / 2 | 14 / 21 / 23 |
| share-19 | 6 / 6 / 6 | 46 / 47 / 53 |
| error-19 | 3 / 3 / 3 | 43 / 32 / 32 |
| nul-20 | 2 / 2 / 2 | 16 / 23 / 23 |
| share-20 | 6 / 4 / 4 | 34 / 39 / 39 |
| error-20 | 3 / 3 / 3 | 45 / 36 / 37 |

`share-20` 提供了依赖级联和状态修整比普通删除更短的具体例子；这里没有观察到 state 比 dependency 更短。plain 保留步骤 s0/s4/s8/s14/s20/s30，沿三级共享链关闭 h6；dependency/state 保留 s0/s4/s19/s30，关闭 h1 后在同一个 s30 扩缩容时观察失败。四步结果使用原始输入中的另一个关闭步骤，不是六步结果的子集。因此，普通删除的最终单步邻域完成，也不排除另一个删除路径到达更短结果。`share-19` 在三种策略下都停在六步，不因结果较长而排除。

耗时分别记录控制器 `elapsed_ms` 和包含输出捕获及日志写入的 CLI `invocation_ms`，快照保留逐例中位数及范围。这是同一主机、每组仅三次的测量，包含启动和文件 IO，且主机负载未受控；不能将结果作为总体加速率或外部库性能结论。进程次数和候选次数也不是单次执行的等价时间成本。

所有正确 fixture 重放及子集核验都放在全部计时测量之后，避免核验夹在策略之间。189 个结果切换正确实现后全部通过。所有 state 结果均不超过六步，对具体输入哈希和指纹相同的结果复用完整子集核验，并记录来源；实际独立执行 **214 个真子集**，覆盖首轮 21 个结果的 259 个逻辑子集位置及后两轮相同结果。差额来自三对合成场景缩成完全相同的输入；没有把缓存命中算成新的执行。没有真子集保持原指纹。超过六步、未确认或未完成的结果会明确标记核验范围，不被排除。

补充边界实验 `results/benchmark-budget-recording-20261017` 使用原九例、一次重复、6 次预算，27 个结果全部保留为 execution_budget，完成搜索数为零。`results/benchmark-passing-screen-20261017` 增加 seed 26 的三种模式：12 个输入中 nul-26 为 Pass，清单保留它且没有替换输入；余下 11 例产生的 33 个缩减全部保留预算耗尽状态和原始步数，没有误报删除最小性。

## 早期九例实验：方法与语料

`scripts/benchmark-reduction.ps1` 比较三种策略，使用同一片段删除调度、参数候选、失败指纹和预算。每次缩减最多执行 200 个工作进程，墙钟预算 60 秒；基线与最终结果各需连续三次保持指纹。三种策略都在启动工作进程前验证候选。

| 策略 | 候选处理 |
|---|---|
| plain | 直接删除片段，拒绝依赖或状态无效的候选 |
| dependency | 删除片段及依赖缺失对象的调用，再校验语义 |
| state | 直接删除片段，再用全新纯模型依次删除结构或状态不合法的调用 |

语料包括原生成器的三个 seed（1、17、20261016），以及各含 0、2、6 组无关操作的两类人工场景。第一类通过别名扩容后经另一别名写入；第二类在扩容和写入之间插入两次读取，使两者不总被首次片段删除同时移除。无关操作覆盖构造、共享、关闭和读取。所有案例使用已有的人工 `error` fixture：拒绝越界写入时错误地修改数据，最终读取发现差异。

这些是确定性的本地测试语料，不代表真实库的缺陷分布。生成器、合成场景和人工缺陷都没有被包装成未知真实漏洞。

以下为 `results/benchmark-state-separated-20261017` 的原始观测；每种策略九次缩减。机器可读数据保存在 [实验快照](evidence/reduction-20261017.json)。

| 策略 | 候选提议数 | 无效候选 | 工作进程执行次数 | 最终步数 |
|---|---:|---:|---:|---|
| plain | 197 | 65 | 186 | 生成器场景 3，其余 4 |
| dependency | 166 | 1 | 219 | 生成器场景 3，其余 4 |
| state | 165 | 0 | 219 | 生成器场景 3，其余 4 |

候选提议数不含基线和最终确认；执行次数包含这些检查。无效候选在父进程被拒绝，不启动工作进程。因此，无效候选减少并不自动带来执行次数下降。

`separated-resize-0` 提供了明确的语义修整证据：state 策略第 7 次执行前的 `delete_block` 候选因删除扩容，额外删除 `write-after-expand`，原因为 `write precondition violated`，且该候选被接受。dependency 在该案例产生一个语义无效候选，state 没有。复现脚本现在会要求这个场景实际出现相应修整记录，防止场景调整后悄悄丢失覆盖。

第一轮六例实验保存在 `results/benchmark-state-repair-20261017`。补充相隔读取场景后扩展为九例；保留两轮数据。两轮都没有显示状态策略在最终步数上占优。各次耗时只测量一次，执行顺序固定，且包含进程启动及文件 IO，不能据此提出统计性能结论。

本次接续又完整执行九例对照，保存至 `results/benchmark-context-continuation-20261017`，新增的语义修整覆盖断言通过。27 条测量的步数、候选数、无效候选数、工作进程次数及失败指纹与上一轮逐条一致；再次独立检查了 111 个真子集。复验摘要保存在实验快照的 `continuation` 字段，仍不将这两轮固定顺序测量作为统计性能研究。

## 正确性证据和声明边界

- 修整只允许删除：引擎检查具体步骤、顺序和轨迹 metadata 不变，每个额外删除必须恰有一条非空原因，再次完整校验候选。
- 单测用独立的布尔状态与标量长度模型枚举七步轨迹的全部 128 个子集；不调用被测修整器或删除函数来计算期望值。
- 全部 27 个结果完成当前策略下的单步删除邻域检查，并连续三次重放相同失败指纹。切换到正确 fixture 后全部通过。
- 九个 state 结果的全部 111 个真子集通过独立位掩码枚举重放，没有更短子集保持原指纹；环境或协议异常会使验证失败。
- 合成边界探针检查预算耗尽、基线变化、最终重放不稳定，以及修改 metadata 的错误修整器。错误修整器即使获得 `confirmed=true` 和 `search_complete`，仍必须是 `deletion_minimal=false`，且保留未决邻居计数。

`confirmed` 表示观测到稳定失败；`deletion_minimal` 还要求完成声明策略下的删除邻域检查且无未决结果。上述真子集核验仅覆盖这些最终结果的固定参数子集。任何一项都不表示任意参数或任意输入的全局最短，也不证明原生根因相同。

状态修整依赖适配器模型准确，特别是被拒绝的转换不得改变模型。当前实现仍需适配器单测维护这一契约；通用依赖前缀检查最坏为二次复杂度。参数简化仍以 JSON 长度严格下降为准，没有参数最小性保证。开发机之外的 Windows CI 复现已通过，见 [验证记录](VALIDATION.md)；本文开头补齐固定本地语料的重复测量，更大外部语料与真实缺陷分布研究仍未完成。

## 复现与证据

在新目录运行，保留所有原始诊断：

```powershell
moon build --target native
& .\scripts\benchmark-reduction.ps1
# 原九例单轮或自定义预算；不足三轮时不保证位置平衡
& .\scripts\benchmark-reduction.ps1 -Repetitions 1 -ExplorationSeeds @() -Budget 200
& .\scripts\verify.ps1
& .\scripts\verify-asan.ps1
```

本轮历史证据分别位于 `results/benchmark-state-separated-20261017`、`results/verify-state-final-20261017`、`results/asan-state-final-20261017`。`results/` 被 Git 忽略，本仓库仅保存实验摘要快照；复现会生成新的原始候选、输入、重放日志和二进制哈希。ASan 仅覆盖文档声明的 C fixture 与 C++ shim，包含新增的共享扩容、缩到零、重新扩容控制场景。
